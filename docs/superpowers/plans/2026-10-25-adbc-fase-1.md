# Driver ADBC (fase 1): piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Snowflake, BigQuery, Databricks, Trino e un ADBC generico attraverso un ponte ADBC,
con i driver scaricati dall'app dal registro `dbc` dopo un popup.

**Architecture:** `platypus-core` conosce i nuovi `DriverKind` e `options`; il nuovo crate
`platypus-drivers` gestisce registro, download, verifica ed estrazione; il nuovo crate
`platypus-driver-adbc` implementa `Connection` su `adbc_driver_manager` in un thread per
connessione. L'app intercetta l'errore "driver mancante" e mostra il popup.

**Tech Stack:** Rust, `adbc_core`/`adbc_driver_manager` 0.24 (arrow 59), arrow 60 nel resto
del workspace, `reqwest` 0.13, `flate2` + `tar`, `sha2`, `serde_yaml_ng`, Tauri 2, React.

**Spec:** `docs/superpowers/specs/2026-10-25-adbc-odbc-design.md` (fase 1).

## Global Constraints

- `unsafe_code = "forbid"` nel workspace: nessun FFI a mano. Il passaggio arrow 59 → 60 è via
  Arrow IPC (serializza con `arrow-ipc` 59, rileggi con `arrow-ipc` 60).
- `FILE_VERSION` = 6; file v5 letti senza cambiamenti.
- User agent delle richieste al registro: `platypus-db/<CARGO_PKG_VERSION>`.
- Driver con licenza `LicenseRef-*` rifiutati.
- clippy pedantic `-D warnings`; commit Conventional Commits in inglese, nessuna riga di
  attribuzione; `git add <file>`.
- Dispatch dei driver in tre posti da tenere allineati: `apps/desktop/src-tauri/src/commands/mod.rs`
  (`connect`), `crates/platypus-mcp/src/connect.rs`, `crates/platypus-conformance/tests/conformance.rs`.
- Testi UI in inglese; icone da `ui/Icon.tsx` o `simple-icons`.

**Rulings rispetto allo spec:**
- Dialetti raggruppati: `Dialect::Ansi` (virgolette doppie, `LIMIT`: Snowflake, Trino, Adbc
  di default) e `Dialect::BigQuery` (accenti gravi, `LIMIT`: BigQuery, Databricks). Oracle/Db2
  in fase 2.
- Fase 1 aggiunge solo `Snowflake`, `BigQuery`, `Databricks`, `Trino`, `Adbc` a `DriverKind`;
  `Oracle`, `Db2`, `Odbc` arrivano con la fase 2.
- La conformance dei driver con ponte è un file a parte (`tests/bridges.rs`) con scenari
  propri (query, tipi, flusso lungo e cancellazione, metadati, errori): la suite esistente
  usa tabelle temporanee, modifica dei dati, kill e explain che Trino `memory` non ha.

## Review Focus

1. Download interrotto o file corrotto: niente driver mezzo installato nella cartella finale
   (estrazione in cartella temporanea + rename), nessun caricamento della libreria.
2. Registro irraggiungibile ma `index.yaml` in cache: il popup funziona comunque per i driver
   già nell'indice; senza cache, errore chiaro.
3. Query annullata o stream eliminato a metà: il thread della connessione torna libero per la
   query successiva (niente blocco del canale).
4. `get_objects` con cataloghi enormi (Trino `system`, Databricks): `schemas()` e `objects()`
   chiedono solo il livello necessario, non tutto l'albero con le colonne.
5. Driver rimosso mentre è caricato (Windows blocca la DLL): la rimozione non fallisce male;
   segna la cartella e la cancella al prossimo avvio.

  (`STRING`, `INT64`, `FLOAT64`, `BOOL`, `TIMESTAMP`, `DATE`, `NUMERIC`, `BYTES`).

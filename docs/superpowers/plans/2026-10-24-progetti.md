# Progetti come spazi di lavoro (Parte B) — Piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raggruppare le connessioni in progetti, ognuno uno spazio di lavoro con le sue
connessioni, tab e cronologia, scelto da una barra di quadrati colorati a sinistra.

**Architecture:** I progetti stanno in `connections.toml` (versione 2) nel crate
`platypus-store`, con le iniziali calcolate lì. Il frontend tiene **tutte** le tab montate,
ognuna col suo `project`, e mostra solo quelle del progetto attivo: sessioni e transazioni
restano aperte e il cambio è immediato. Il codice nuovo del frontend sta in
`apps/desktop/src/projects/`.

**Tech Stack:** Rust (`platypus-store`, comandi Tauri), React + TypeScript, scenari E2E su
WebView2.

**Spec:** `docs/superpowers/specs/2026-10-24-grafica-e-progetti-design.md`, Parte B.

## Deviazione voluta dalla spec

La spec (B5) salva le tab di ogni progetto sotto una chiave propria
(`platypus.workspace.v2.<projectId|all>`) e le ripristina al cambio. Le sessioni degli editor
però sono legate alla tab (`sessions` per chiave di tab in `App.tsx`): smontare le tab di un
progetto chiuderebbe sessioni e transazioni, che la spec vuole aperte. Il piano quindi tiene
tutte le tab montate con un campo `project` e salva **un solo** workspace
(`platypus.workspace.v2`) con il progetto di ogni tab. Il comportamento visibile è quello
della spec; cambia solo il formato in `localStorage`.

## Global Constraints

- Branch `group-projects` da `main` aggiornato (la funzione non ha una lettera nella tabella
  dei lock). Prima di scrivere codice, seguire `CLAUDE.md` "Prima di iniziare": aggiungere
  alla tabella "Lock dei gruppi" la riga `Progetti (spazi di lavoro)` con
  `🔒 <nome> · group-projects · <data>`, in un commit `chore(roadmap): lock progetti`
  pushato su `main`.
- Commit in inglese, Conventional Commits, senza nominare Claude; `git add <file>`, mai `-A`.
- `connections.toml` passa a `version = 2`. Un file v1 si legge e si riscrive come v2 al primo
  salvataggio. Un lettore v1 rifiuta il v2 con il messaggio che già esiste
  ("written by a newer PlatypusDB").
- Il campo `folder` delle connessioni sparisce dal modello; se un file lo contiene viene
  ignorato in lettura.
- Validazione dei progetti: nome non vuoto (dopo il trim) e unico senza distinguere maiuscole,
  colore `#rrggbb`, iniziali da 1 a 2 caratteri (grafemi).
- Iniziali calcolate: iniziali delle prime due parole del nome ("Cliente Rossi" → "CR"),
  oppure le prime due lettere se è una parola sola ("Interno" → "IN"), maiuscole.
- "Tutte le connessioni" non è un progetto salvato: nel frontend è `activeProject === null`.
- Scorciatoie: `project.switch.1` … `project.switch.9` = `Mod+1` … `Mod+9` (`Mod+1` = Tutte
  le connessioni, poi i progetti in ordine), `project.next` / `project.previous` =
  `Mod+Alt+PageDown` / `Mod+Alt+PageUp`.
- Colori proposti nel dialog del progetto (8): `#6c63ff`, `#d08f20`, `#3d7bf7`, `#a46be0`,
  `#2f9e6e`, `#e05a5a`, `#1aa3b8`, `#8a93a3`.
- Il titolo della finestra richiede il permesso `core:window:allow-set-title` in
  `apps/desktop/src-tauri/capabilities/`.
- Le classi CSS usate dagli E2E esistenti non cambiano. Classi nuove: `.project-rail`,
  `.project-square` (con `data-project` = id o `all`, classe `active`, classe `tx` se una tab
  del progetto ha una transazione aperta), `.project-dialog`, `.project-chips`.
- Verifica di ogni task (CLAUDE.md, "Dopo un'implementazione" punto 2): `cargo fmt --all
  --check`, `npm --prefix apps/desktop run build`, `cargo clippy --workspace --all-targets`
  (pedantic, `-D warnings`), `cargo test --workspace --exclude platypus-desktop`; per i task
  di UI anche `npm --prefix apps/desktop run tauri build -- --no-bundle` e
  `npm --prefix apps/desktop run e2e`.

## Review Focus

1. **Un file `connections.toml` con progetti aperto da PlatypusDB 0.2.0**: deve rifiutarlo
   con un messaggio chiaro, non cancellare i progetti salvando (test nel Task 1).
2. **Una connessione eliminata** sparisce da tutti i progetti, anche quelli non attivi, e un
   progetto che la conteneva non mostra righe fantasma (test nel Task 1 e nel Task 6).
3. **Cambio di progetto con una transazione aperta**: la sessione resta aperta, il quadrato
   del progetto lasciato mostra l'avviso, tornando si ritrova la stessa transazione (test nel
   Task 4).
4. **Progetto eliminato mentre è attivo con modifiche non salvate**: chiede conferma prima di
   chiudere le sue tab; se si annulla, il progetto resta (test nel Task 6).
5. **Workspace salvato da 0.2.0** (`platypus.workspace.v1`): le tab tornano tutte in "Tutte le
   connessioni" e niente va perso (test nel Task 3).

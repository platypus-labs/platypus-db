Bases de données

Une page par base de données : comment s'y connecter, ce que demande la connexion, ce qui fonctionne et ce qui ne fonctionne pas, et sur quelles versions tourne la suite de tests. Se connecter explique ce que toutes les bases de données ont en commun (SSH, proxy, trousseau, projets), Dépannage les erreurs, et FEATURES.md est la référence par fonctionnalité.

Azure SQL, Supabase, Neon, AlloyDB, le cloud de Turso, Snowflake, BigQuery, Databricks et IBM Db2 sont listés parce que l'application a pour eux un pilote, un préréglage ou une tuile ; personne n'a essayé l'application sur ces services (voir « Testé sur » plus bas et sur chaque page).

Ce qui fonctionne où

« Lignes » désigne la modification dans la grille. « Admin » désigne les onglets serveur de Activité du serveur… (sessions, verrous, tableau de bord, instructions les plus coûteuses, tables et index, paramètres, utilisateurs et rôles, maintenance). Un tiret signifie « non disponible » ; « non testé » signifie que l'application ne le bloque pas mais que rien ne l'exécute.

« Admin » est désactivé sur CockroachDB et YugabyteDB parce que ces serveurs n'ont pas une partie de ce que les onglets appellent (CockroachDB n'a ni pg_blocking_pids ni pg_terminate_backend, YugabyteDB garde ses verrous ailleurs). Les bases de données sans SQL (MongoDB, Redis, Elasticsearch, Cassandra) n'ont pas non plus d'éditeur de tables, de diagramme ER, de comparaison de schémas, de constructeur de requêtes, d'import SQL, d'instantanés avant modifications ni de plans de requête ; leurs pages disent ce qu'elles ont à la place.

Toutes les bases de données ont l'éditeur, la grille et le navigateur. Les lignes de la grille sont retrouvées par la clé primaire de la table, par une clé unique sur des colonnes non nulles, ou par une clé virtuelle que vous définissez.

Pilotes téléchargés à la première utilisation

PostgreSQL, MySQL, SQL Server, SQLite, libSQL, ClickHouse, MongoDB, Redis, Elasticsearch et Cassandra sont intégrés à l'application. Les autres demandent une bibliothèque que l'application télécharge une seule fois :

Base de donnéesCe qui est téléchargéD'où
DuckDBLa bibliothèque de DuckDB, 2.0.0La version de DuckDB sur GitHub

IBM Db2IBM Data Server Driver for ODBC and CLI 12.1.4 (Windows)IBM
Snowflake, BigQuery, Databricks, Trinoleur pilote ADBCle registre de pilotes dbc (Columnar)

Quand vous choisissez la base de données pour une nouvelle connexion, et que la bibliothèque n'est pas sur cette machine, une fenêtre s'ouvre au-dessus du formulaire pour dire de quoi il s'agit, sa version et sa taille, sa licence et d'où elle vient, et que le téléchargement est vérifié par un SHA-256. Télécharger la récupère (Windows demande la permission d'administrateur pour enregistrer le pilote d'IBM) ; Annuler laisse le formulaire utilisable. La proposition revient à Tester la connexion et à la première ouverture. La vérification ne lit que cette machine, donc elle apparaît même hors ligne, alors que le téléchargement demande le réseau. Paramètres › Pilotes liste, met à jour et supprime ce qui a été téléchargé.

Versions

La plus ancienne version contre laquelle chaque base de données est vérifiée, et ce sur quoi tourne la suite de conformité (docker/compose.yml et le profil versions). Un serveur plus ancien que le minimum se connecte avec un avertissement disant que certaines fonctionnalités peuvent ne pas marcher, sauf Cassandra, ScyllaDB, Elasticsearch et OpenSearch, qui le refusent.

Agents

Agents et la CLI fonctionne sur toutes les bases de données ci-dessus. Les différences sont sur chaque page : comment une session en lecture seule est créée (le serveur refuse les écritures sur PostgreSQL, CockroachDB, YugabyteDB, MySQL, MariaDB, SQLite, DuckDB et ClickHouse ; partout ailleurs, seule la vérification de l'instruction s'applique), et ce qui est refusé (explain sur MongoDB, Redis, Elasticsearch et Cassandra ; get_er_diagram sur MongoDB, Redis et Elasticsearch ; propose_edits partout où la grille ne modifie pas les lignes par clé : Redis, Elasticsearch, Cassandra, ClickHouse et les bases de données ADBC ; sur MongoDB, il désigne les documents par _id). server_activity et top_queries fonctionnent sur PostgreSQL, MySQL, MariaDB et SQL Server.

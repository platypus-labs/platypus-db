DuckDB

DuckDB 在应用内部运行，与 SQLite 类似：没有服务器、主机、用户或密码。与 SQLite 不同的是，应用本身不带 DuckDB 的库；它会在第一次打开 DuckDB 数据库或数据文件时下载它。

首次使用：DuckDB 的库

当你为新连接选择 DuckDB，而这台机器上没有该库时，表单上方会弹出一个窗口：下载 DuckDB？它会显示软件包（DuckDB 2.0.0，来自 DuckDB 在 GitHub 上的发布版，MIT 许可证）、大小和来源，并用 SHA-256 校验下载。下载会把它放进应用的数据文件夹，所有 DuckDB 数据库和文件共用一份；取消则表单仍可使用，并在测试连接时和第一次打开时再次提示。设置 › 驱动会列出该库并可移除它。

应用为 Windows（x64、ARM64）、Linux（x64、ARM64）和 macOS（两种处理器共用一个库）下载它。应用恰好使用它构建时的版本（2.0.x），如果安装的是其他版本，就提供这个版本。离线且缺少该库时，连接无法打开。

连接

选择 DuckDB 并给出数据库文件的路径，或粘贴 URL：

你粘贴的内容含义
duckdb:///home/ana/analytics.duckdb该文件，不存在时会创建（其文件夹必须存在）
duckdb:///C:/data/analytics.duckdbWindows 盘上的文件
duckdb:///:memory:应用的各会话共享的内存数据库
作为路径的 :memory:<name>按名称区分的、独立的内存数据库

把数据文件当作数据库。 以 .csv、.tsv、.json、.ndjson、.jsonl、.parquet、.xlsx、.xlsm、.xls 或 .ods 结尾的路径，会作为基于该文件的内存数据库打开（也可以把文件拖到窗口上）。CSV、TSV、JSON、NDJSON 和 Parquet 会变成一个以文件命名的视图，DuckDB 每次查询时都会重新读取它；工作簿的每个工作表会变成一张表，只加载一次。CSV 或 TSV 会先经过检查（每一行的值数量必须与标题行一致），检测其文本编码（或由你指定），导入选项可以让你跳过有问题的行。

扩展不会自动下载或加载；只有库中内置的扩展（Parquet、JSON）可用。

权限

由操作系统决定：读取文件的权限，以及写入文件及其文件夹才能更改任何内容的权限。同一时间只有一个进程可以以写入方式打开 DuckDB 文件，所以当应用打开着某个文件时，另一个程序（例如 duckdb 命令行）无法使用它；应用对同一个文件的各会话共享一个实例。因此不提供终端模式。

可用功能

  • 在表格中按主键（或非空列上的唯一键，或虚拟键）编辑数据。数据文件会读入内存：CSV、JSON 或 Parquet 视图不是表，无法编辑，对工作簿工作表的编辑也不会写回文件。
  • 手动提交和回滚；取消语句（duckdb_interrupt）。
  • 执行计划显示计划（EXPLAIN (FORMAT JSON)）；分析执行计划在一个会回滚的事务中运行语句，而当你已打开事务时会被拒绝。
  • 参数标签页：DuckDB 的设置。没有会话、锁、仪表板、用户或语句标签页。
  • 元数据搜索、对象 DDL、模式工具。DuckDB 很少能就地修改，所以更改表会重新创建它并复制其行。
  • 导入通过 DuckDB 的 appender 进行，在会话的事务中。

代理

只读代理和只读连接以只读方式打开数据库文件，前提是应用的其他会话没有已经打开它；内存数据库或数据文件永远不是只读的，那里由语句检查来阻止写入。代理的 DuckDB 会话无法读取或写入其他文件，也无法加载扩展，并在每次调用之后关闭文件，以便应用可以打开它。query_across_databases 在它自己的 DuckDB 中运行，应用会像这个一样下载它。见代理和 CLI。

已知限制

  • Excel 文件由应用自己的读取器读取，而不是 DuckDB 的 Excel 扩展。
  • 不会加载 2.0.x 以外的 DuckDB 版本。

测试环境

一致性测试套件在一个 DuckDB 文件上运行，使用与应用绑定相匹配的库：事务、计划、表编辑、特殊值、128 位和无符号数字以及带时区的时间。

另见：连接、故障排除。

The connections file (.platypusconn)

What Export connections writes and Import connections › PlatypusDB reads. The code is crates/platypus-sync/src/export.rs.

Plain file

UTF-8 JSON:

{
  "format": "platypusdb-connections",
  "version": 1,
  "projects": [
    {
      "name": "Team",
      "folders": [["Servers"], ["Servers", "Prod"]],
      "connections": [{ "id": "…", "name": "Prod", "driver": "postgres", "host": "db.example.com", "user": "alice", … }],
      "placement": { "<connection id>": ["Servers", "Prod"] }
    },
    { "connections": [ … ] }
  ]
}
  • A project without name holds the connections outside any project, or all of them when the export drops projects.
  • folders lists each folder as its names from the root, parents first; placement gives the folder of the connections that are in one.
  • Each connection has the fields of a shared project's connection (ShareConnection in portable.rs): an allow-list, so a field added later to the saved connection stays out until someone adds it there. Never written: passwords in clear files, password commands, .pgpass, certificate and key paths, keychain ids, secret driver options, the shell commands run before connecting and after disconnecting. A network profile is written into the connection; profiles themselves are not exported.
  • A file with a higher version is refused, not guessed at.

Encrypted file

With a password the JSON above is sealed in the sync container (crypto.rs): the magic PLATYSYN, the container version, the Argon2id settings, a salt and a nonce, then the JSON encrypted with AES-256-GCM; the header is authenticated too. Only an encrypted file may carry, per project, a secrets object:

"secrets": { "<connection id>": { "password": "…", "ssh": "…", "jumps": ["…", null] } }

ssh is the password of the connection's SSH server or the passphrase of its key; jumps gives the same for each jump host behind it, in the order of the jump chain (null for one without). Files written before jumps existed simply lack it. A wrong password, or any changed byte, gives an error and no data.

Reading

The file is untrusted like a shared project's: each connection gets a new id, its ${env:…} references are held until the user edits them, it cannot make the ODBC driver manager load a library, and agents are kept out of it until the user lets them in.

A connection like a saved one (same database, server, port, database name, user and SSH hops) starts unticked; one reached another way is never taken for it, so a file cannot send saved passwords to another server. Ticked, it replaces the saved one by default: the saved connection keeps its id, so its projects, tabs and history, the passwords the file does not bring, and what only this machine set: certificate and key paths, the password command, options the file leaves out, agent access and its restrictions.

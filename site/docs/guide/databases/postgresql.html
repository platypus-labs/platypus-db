PostgreSQL, CockroachDB, YugabyteDB, TimescaleDB and the rest

One driver, built on tokio-postgres, speaks the PostgreSQL protocol. It opens PostgreSQL 12 and later, and the servers and services that speak the same protocol. Nothing is downloaded: the driver is part of the app.

Connect

Pick PostgreSQL in the grid of databases, or paste a URL: the form fills itself in.

You pasteRead as
postgres://user:pass@host:5432/db?sslmode=require (or postgresql://)the URL form; the default port is 5432
jdbc:postgresql://host/db?sslmode=requirea JDBC URL, as DBeaver and DataGrip keep them
host=db port=5432 dbname=shop user=app sslmode=requirea libpq connection string
Host=db;Database=shop;Username=app;Password=…an Npgsql connection string

URL parameters the app knows: sslmode, sslrootcert, sslcert, sslkey, application_name, connect_timeout and pgbouncer=true. Any other parameter is left out, and the form says which. A failover list of hosts (h1:5432,h2:5432) keeps the first host.

TLS follows libpq's sslmode:

ModeWhat happens
disableno TLS
prefer (the default)TLS if the server offers it, otherwise plain; the certificate is not checked
requireTLS, certificate not checked
verify-caTLS, the certificate chain is checked, the host name is not
verify-fullTLS, chain and host name are checked

The chain is checked against the file in sslrootcert if there is one, otherwise against the system's trusted certificates. A client certificate (sslcert and sslkey) is sent in every mode that uses TLS.

Signing in is by password, or by a token that a cloud's command-line tool makes at each connection: AWS IAM (aws), Google Cloud IAM (gcloud) and Microsoft Entra ID (az) are in the connection's Authentication choice. The tool must be installed and signed in on your machine. Or by Kerberos, below.

Kerberos (GSSAPI). Choose Kerberos ticket (GSSAPI) under Password from. The password field goes away: no password is asked, saved or sent. If the server asks for one, or lets you in without asking for Kerberos, the connection is refused and says so.

  • The service name is postgres unless you fill it in (the server's krb_srvname). The ticket asked for is service/host, in your default realm: the host must be the name in the service's principal, not an IP address or an alias, since the app does not look it up. Through an SSH tunnel or a port forward it is still the server's name.
  • The user is the PostgreSQL role, which the server maps from your principal (include_realm and pg_ident.conf). Left empty, the app uses your system user name.
  • The ticket on Linux comes from kinit, in the cache that KRB5CCNAME names (or the default one), or from a keytab: with KRB5_CLIENT_KTNAME set, Kerberos gets the ticket by itself. Those variables must be set where the app starts. On Windows it is the ticket of your Windows session.
  • Without a ticket the test says what to run: kinit, the two variables and klist, followed by Kerberos' own text. The same goes for an expired ticket, an unknown service and an unreachable KDC.
  • psql, pg_dump and pg_restore sign in the same way (PGKRBSRVNAME, PGREQUIREAUTH=gss, and no PGPASSWORD). Their copy of libpq must have been built with GSSAPI.
  • Which builds have it. The Windows (SSPI) and Linux (GSSAPI, MIT Kerberos) packages. The macOS ones do not: no Mac has built it yet, and the form says so. The Cargo feature kerberos of platypus-driver-pg turns it on; without it nothing about Kerberos is linked or runs.
  • GSS encryption (hostgssenc, gssencmode) is not used: use TLS for encryption, with hostssl or host lines. A krbsrvname in a pasted URL is left out, like any other parameter the app does not know.

Poolers. Behind PgBouncer, Supavisor or Neon's pooler in transaction mode, choose Transaction mode in the form (or add pgbouncer=true to the URL). Statements then run unnamed, because the next transaction may be on another server session. The form suggests it for hosts ending in .pooler.supabase.com and for Neon hosts with -pooler in the name. In that mode the PL/pgSQL debugger is off, and agents' read-only sessions rely on the statement check alone.

The other servers have tiles of their own, which only set defaults:

TileDefaults it sets

Privileges

Browsing needs only what the server shows the login. The administration tabs read these:

  • Sessions and Locks: pg_stat_activity and pg_locks. The app lists the client sessions the server returns; how much of other users' sessions and statements the server shows to the login is the server's rule, which the app does not check. Cancel statement and End session call pg_cancel_backend and pg_terminate_backend; the server decides whether the login may.
  • Costliest statements: the pg_stat_statements extension. Without it the tab says how to turn it on (add it to shared_preload_libraries, restart, CREATE EXTENSION).
  • Tables and indexes: pg_stat_user_tables and pg_stat_user_indexes.
  • Parameters and Dashboard: pg_settings, pg_stat_database, pg_stat_activity and the replication views; the standbys are listed only to a member of pg_monitor. A figure the login cannot read shows "—" and why.
  • Users and roles: pg_roles and pg_auth_members; changing them needs the rights the statements need.
  • Maintenance: VACUUM, ANALYZE and REINDEX on the table.
  • Back up… and Restore… run pg_dump, pg_restore and psql, which must be on the PATH.
  • Debug… needs the pldebugger extension on the server.

What works

  • Data editing in the grid, by primary key (or a unique key on non-null columns, or a virtual key you set). Arrays and composite values edit one element or field per line.
  • Transactions with manual commit, and statements cancelled on the server.
  • Explain and Explain analyze; the plan is read from PostgreSQL's JSON or text.
  • Several databases per connection, partitions, PostGIS geometries, arrays and composite types.
  • Imports and copies into PostgreSQL use COPY.
  • Every administration tab above, the PL/pgSQL debugger, and schema tools (table editor, ER diagram, comparison).

CockroachDB and YugabyteDB open with the same driver, but the app finds out which server it is, and the server tools that rely on PostgreSQL's own views are off: no sessions, locks, dashboard, statements, tables and indexes, parameters, users or maintenance tabs, and no debugger. CockroachDB has its own plan format (Explain and Explain analyze work) and imports go as INSERT statements instead of COPY. A CockroachDB table without a key is edited by its hidden rowid. TimescaleDB (tested), Supabase, Neon and AlloyDB (not tested against the services) are PostgreSQL to the app, with everything above; what a hosted service restricts for your role is its own rule.

Agents

Read-only agents and read-only connections open the session with default_transaction_read_only (PostgreSQL, CockroachDB and YugabyteDB), so the server itself refuses writes; behind a transaction-mode pooler only the statement check does. server_activity and top_queries work on PostgreSQL proper, not on CockroachDB or YugabyteDB. See Agents and the CLI.

Known limits

  • Older than 12: the app connects and warns that some features may not work.
  • The debugger is off behind a transaction-mode pooler.
  • Terminal mode needs psql on the PATH.

Tested on

The conformance suite runs on PostgreSQL 12, 14, 16 and 17, TimescaleDB 2.30 on PostgreSQL 17, CockroachDB 26.2 and YugabyteDB 2025.2, plus PgBouncer in transaction mode, a client certificate over mutual TLS, and the debugger on a server with pldebugger. Supabase, Neon and AlloyDB are not tested: they are the PostgreSQL driver with defaults.

Kerberos is tested with a real ticket from a real KDC (MIT Kerberos, in the kerberos profile of docker/compose.yml) on PostgreSQL 17, from a Linux client with GSSAPI: a ticket from kinit, a keytab, TLS, psql, no ticket, an expired ticket and a wrong service name. The login through Windows' SSPI has not been tried with a real ticket: a Windows machine outside a domain cannot reach the test KDC without changing system settings (ksetup). On Windows only what happens without a ticket is tested. A server's sspi line (PostgreSQL on Windows) has not been tried either.

See also: Connecting, Troubleshooting.
